## 🎯 Goal
Robustly calibrate TEITOK bounding box (bbox) coordinates, which depend heavily on page-image width and height. The solution provides a scalable approach to spatial alignment even when original companion images or specific ALTO `MeasurementUnit` variables are missing.

## 🧭 Architecture
1. **3-Tier Calibration Priority**: Per-page scaling dynamically resolves by checking for: 1) Companion image dimensions (most accurate), 2) User-set DPI based on ALTO units (`inch1200`, `mm10`, `pixel`), or 3) PrintSpace dimensions as a fallback.
2. **Consolidated Coordinate Math**: All divergent transforms were unified into a single regex-based primitive, `api_util/bbox_scale.py`. This eliminated `ParseError` crashes caused by legacy `ElementTree` implementations when encountering anomalies like `</n>` tags.
3. **API and Pipeline Integration**: The structural alignments are enabled post-factum via the `POST /rescale` endpoint. Additionally, variables like `IMAGE_DPI` and `ALTO_DPI` were added to `summarize_nt_udp.py` and threaded through `api_4_stats.sh` to resolve a P0 regression that was causing Stage 4 crashes on batch runs.
4. **Performance Integrity**: The API processes bounding coordinates efficiently by leveraging the underlying categorization algorithm's strict quality-score thresholds to quickly drop noisy lines, circumventing queue congestion.

## ⏳ Open / Next

- **Resolution-Independent Coordinates**: Await confirmation from the TEITOK-team regarding a migration to relative/resolution-independent coordinates.
