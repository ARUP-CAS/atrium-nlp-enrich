## 🎯 Goal
Let **any Flexiconv-supported format** be taken as raw text input (as agreed at the meeting —
*not* about post-processing outputs). Concretely: ingest non-tabular documents (pdf, docx, odt,
rtf, html, md, txt, epub, tei, conllu, …) **and** keep CSV/XLSX tables working unchanged.

## 🧭 Architecture (confirmed with the user)
```
 Tabular (CSV/XLSX)  → api_1 → api_2 → api_3 → api_4 ─┐   (UNCHANGED)
                                                      ├─► TEITOK XML / CoNLL-U / CSV
 Non-tabular formats → flexiconv convert ─────────────┘   (NEW: replaces stages 2–4)
                                                      ↘ keywords.py (reads .conllu AND .teitok.xml)
                                                      ↘ llm_run.py  (reads .csv    AND .teitok.xml)
```
**Five locked decisions:**
1. Non-tabular inputs are converted by **Flexiconv directly to TEITOK XML**, *replacing*
   UDPipe/NameTag stages 2–4 (they do **not** pass through them).
2. Flexiconv output = **TEITOK XML only** (its native target).
3. Keyword + LLM enrichment stay **outside** Flexiconv — they are extended to discover and read
   the produced `.teitok.xml` via a **shared, stdlib-only** reader, so they never import Flexiconv.
4. **CSV/XLSX untouched** — keep stages 1–4 exactly as today.
5. Flexiconv is an **optional dependency** (lazy import, separate requirements file, clear
   install-hint error); the readers are pure stdlib.

➡️ Net: with default config **nothing changes**; non-tabular docs become first-class inputs.

## 🧱 File contract
**New:** `api_flexiconv.sh` (peer to `api_1..4`, paradata-tracked, scans `INPUT_DOCS_DIR` for
`FLEXICONV_FORMATS`), `api_util/flexiconv_convert.py` (the *only* module touching Flexiconv —
library-first with a CLI `flexiconv -t teitok` fallback, raises `FlexiconvNotInstalled` if
neither present), `api_util/teitok_read.py` (stdlib `ElementTree`, namespace-agnostic; `<pb>`→
page, `<lb>`→line, `<s @text>`/`<tok>` join, lemma/pos when present;
`read_teitok_rows/_text/_tokens`, `doc_id_from_path`), `requirements_flexiconv.txt`, plus tests
+ a `sample.teitok.xml` fixture.
**Edited:** `keywords.py` (glob `.conllu` + `.teitok.xml`; helpers dispatch by extension —
`_extract_surface_text`/`_extract_lemmas` split into `*_conllu` bodies), `llm_run.py` +
`llm_utils.py` (glob `.csv` + `.teitok.xml`; new `read_input_rows()` synthesises `categ=""` for
TEITOK rows; output naming via `doc_id_from_path` so `X.teitok.xml → X_enriched.json`),
`config_api.txt` (`INPUT_DOCS_DIR`, `FLEXICONV_FORMATS`), `README.md`.

## ⚠️ Known caveats (documented, by design)
- **TEITOK from plain docs lacks lemma/POS** → the **legacy** keyword method yields few lemmas;
  **yake/keybert** (surface text) work regardless.
- **Double-suffix** `.teitok.xml` → `doc_id_from_path` strips it for clean ids/output names.
- **Flexiconv missing** → only the conversion step fails (clear install hint, file skipped);
  readers + tabular pipeline unaffected.
- **Layout-free formats** (md/txt/docx/html, no `<pb>`/`<lb>`) → single page, one row per `<s>`.
