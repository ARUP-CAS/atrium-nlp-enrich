## 🎯 Goal
Let **any Flexiconv-supported format** be taken as raw text input (as agreed at the meeting —
*not* about post-processing outputs). Concretely: ingest non-tabular documents (pdf, docx, odt,
rtf, html, md, txt, epub, tei, conllu, …) **and** keep CSV/XLSX tables working unchanged.

## 🧭 Architecture
1. **Pre-processing hook (`api_flexiconv.sh`)**: Runs *before* standard pipelines. Finds files
   matching `$FLEXICONV_FORMATS` in `INPUT_DOCS_DIR` and converts them **to TEITOK XML** inside
   the intermediate `TEITOK` dir.
2. **Optional dependency**: Uses python `flexiconv` lib if installed, falls back to `flexiconv` CLI,
   skips smoothly if missing. Pinned directly to the remote Git repository in `requirements_flexiconv.txt`.
3. **Stdlib-only readers (`teitok_read.py`)**: `keywords.py` and `llm_run.py` now check the
   `TEITOK` output dir. If they see a `.teitok.xml` they read it via `xml.etree.ElementTree`
   without relying on Lxml or third-party parsers.
4. **Unified downstream handling**: `llm_utils.py` synthesizes `categ=""` and `quality_score=0.0`
   for these layout-free TEITOKs so the quality filter `_should_process_line` digests them normally;
   readers + tabular pipeline unaffected.
- **Layout-free formats** (md/txt/docx/html, no `<pb>`/`<lb>`) → single page, one row per `<s>`.
- **Structural formats** (PAGE XML, hOCR) → Coordinate scaling successfully bound and verified.
