**Labels**: `enhancement`, `validation`, `pipeline`
**Status**: 📋 `Planned` — strategy finalized to treat TEITOK validation as a formal output contract, mirroring the AMCR validation in `atrium-translator`. Implementation will introduce a hard gate prior to dataset packaging. 

## 🎯 Goal
Prevent malformed TEITOK XML from causing silent failures in downstream visualizers and search indexes. Catch schema violations at the point of generation in `api_4_stats.sh` so that poisoned data never enters the final FAIR dataset or LINDAT release.

## 🧭 Architecture
1. **Pinned Schema (`schemas/teitok/`)**: The official TEITOK XSD will be vendored directly into the repository. This guarantees reproducible builds without network dependencies and ensures the dataset release contract is fully auditable.
2. **Reusable Validator (`api_util/validate_teitok_xml.sh`)**: A standalone bash script wrapping `xmllint` (via `libxml2-utils`). Designed to iterate over *all* generated XML files, reporting specific filenames and XSD diagnostics on failure.
3. **Pipeline Gate (`api_4_stats.sh`)**: The validator is invoked *after* TEITOK compilation and post-processing, but *before* packaging. Any non-zero exit from the validator halts the pipeline immediately (`exit 1`).
4. **CI Enforcement**: Validation is explicitly run within the centralized GitHub Actions workflow templates. Test fixtures (both valid and intentionally invalid) prove the gate's effectiveness during every PR and push.

## ✅ Verification plan (from the issue) — what needs running live
1. **Validator Unit Tests**: Run `validate_teitok_xml.sh` against a valid TEITOK fixture → `exit 0`. 
2. **Invalid Fixture Rejection**: Run the validator against an intentionally malformed fixture (`CTX_invalid.teitok.xml`) → `exit 1` with filename and structural diagnostics printed to stderr.
3. **Pipeline Integration**: Execute `api_4_stats.sh` locally. Verify that the script successfully validates all outputs and proceeds to statistics/packaging.
4. **CI Workflow Execution**: Ensure the GHA test runners successfully install `libxml2-utils` and that the automated tests actively fail if the invalid fixture bypasses the gate.
