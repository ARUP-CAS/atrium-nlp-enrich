# Plan: Flexiconv-supported input formats (Issue #10) by Opus

**Architecture confirmed with the user:**

```
 Tabular (CSV/XLSX)   →  api_1 → api_2 → api_3 → api_4 ─┐         (UNCHANGED)
                                                        ├─► TEITOK XML / CoNLL-U / CSV
 Non-tabular formats  →  flexiconv convert ─────────────┘         (NEW: replaces 2–4)
                              (input → TEITOK XML only)
                                                        ↘ keywords.py  (reads .conllu AND .teitok.xml)
                                                        ↘ llm_run.py   (reads .csv    AND .teitok.xml)
```

Decisions:
1. **Non-tabular inputs are converted by Flexiconv directly to TEITOK XML**, *replacing*
   stages 2/3/4 — they do **not** go through UDPipe/NameTag.
2. **Flexiconv output = TEITOK XML only** (its native target).
3. **keyword extraction and LLM enrichment stay outside Flexiconv.** They are not called
   by the conversion step. Instead they are **extended to discover and read the produced
   `.teitok.xml` files** via a shared, **stdlib-only** TEITOK reader — so they never
   import Flexiconv.
4. **CSV/XLSX untouched** — they keep stages 1–4 exactly as today.
5. **Flexiconv is an optional dependency** — only the conversion step needs it (lazy
   import, separate requirements file, clear install-hint error). The TEITOK readers are
   pure stdlib, so `keywords.py`/`llm_run.py` need no new dependency.

Outcome: with default config nothing changes. Non-tabular documents become first-class
inputs that reach TEITOK (and then keywords/LLM) without UDPipe/NameTag.

## Design

### 1. New conversion step — `api_flexiconv.sh` + `api_util/flexiconv_convert.py`

Peer to `api_1..4_*.sh`. Sources `config_api.txt`, paradata-tracked like the others.
Scans `INPUT_DOCS_DIR` for the extensions listed in `FLEXICONV_FORMATS`, and per file:
`python3 api_util/flexiconv_convert.py "$f" --out-dir "$TEITOK_OUTPUT_DIR"` → writes
`<doc_id>.teitok.xml` into `TEITOK_OUTPUT_DIR` (the same dir api_4 writes TEITOK).

`api_util/flexiconv_convert.py` (only module that touches Flexiconv; lazy import):
```python
FLEXICONV_EXTENSIONS: frozenset      # default non-tabular exts; EXCLUDES .csv/.xlsx
INSTALL_HINT: str
class FlexiconvNotInstalled(RuntimeError): ...
def normalize_ext_list(s) -> frozenset
def is_flexiconv_format(path, allowed=None) -> bool
def flexiconv_available() -> bool                 # never raises (lib OR CLI present)
def convert_to_teitok(in_path, out_dir) -> str    # writes <stem>.teitok.xml, returns path
```
`convert_to_teitok` tries the Flexiconv **Python library** first (lazy `import flexiconv`,
convert to the `teitok` target), falling back to the **CLI**
(`shutil.which("flexiconv")` → `subprocess.run(["flexiconv","-t","teitok",in,out], timeout=...)`),
and raises `FlexiconvNotInstalled(INSTALL_HINT)` if neither is present. The exact library
entry point is verified at implementation; the lib→CLI fallback keeps it robust either way.

### 2. Shared TEITOK reader — `api_util/teitok_read.py` (stdlib only, reused everywhere)

Parses TEITOK/TEI XML with `xml.etree.ElementTree`, namespace-agnostic (match local tag
names, same defensive style as `api_util/teitok_alto.py`). Handles `<pb n>` (page),
`<lb>` (line), `<s text="…">` (sentence; prefer `@text`, else join `<tok>`), `<tok>`
attributes (`@join`/spaceAfter, and `@lemma`/`@pos`|`@type` when present).
```python
def read_teitok_rows(path)   -> list[dict]   # [{"page_num":int,"line_num":int,"text":str}]
def read_teitok_text(path)   -> str          # surface text ("\n".join of rows)
def read_teitok_tokens(path) -> list[dict]   # [{"form","lemma","upos","space_after"}]
def doc_id_from_path(path)   -> str          # strips .conllu / .teitok.xml → clean id
```
Layout-free sources (md/txt/docx/html → no `<pb>`/`<lb>`) yield a single page, one row
per `<s>`.

### 3. Extend `keywords.py` (discover + read `.teitok.xml`)

- **Glob** (`:521`): gather both extensions —
  `all_files = sorted(p for p in input_path.iterdir() if p.suffix.lower()==".conllu" or p.name.lower().endswith(".teitok.xml"))`.
- **Zero call-site churn:** make the two existing helpers dispatch by extension internally.
  Rename current bodies to `_extract_surface_text_conllu`/`_extract_lemmas_conllu`, then:
  ```python
  def _extract_surface_text(file_path):
      if file_path.lower().endswith(".teitok.xml"):
          import teitok_read; return teitok_read.read_teitok_text(file_path)
      return _extract_surface_text_conllu(file_path)
  def _extract_lemmas(file_path):
      if file_path.lower().endswith(".teitok.xml"):
          import teitok_read
          return [t["lemma"].lower() for t in teitok_read.read_teitok_tokens(file_path)
                  if t.get("upos") in {"NOUN","PROPN","ADJ"} and (t.get("lemma") or "").isalpha()]
      return _extract_lemmas_conllu(file_path)
  ```
  Call sites `:161` (legacy), `:180` (yake), `:263` (keybert) stay unchanged.
- Derive `document_id` via `teitok_read.doc_id_from_path` so `.teitok.xml`/`.conllu`
  produce clean ids.
- Caveat: TEITOK from non-annotated docs may lack lemma/POS → the **legacy** method yields
  few lemmas; **yake/keybert** (surface text) work regardless. Documented.

### 4. Extend `llm_run.py` + `llm_utils.py` (discover + read `.teitok.xml`)

- **Glob** (`llm_run.py:615`): gather `*.csv` **and** `*.teitok.xml`; output naming via
  `doc_id_from_path` so `X.teitok.xml` → `X_enriched.json` (not `X.teitok_enriched.json`).
- **Row read:** add `read_input_rows(input_path)` in `llm_utils.py` near
  `_should_process_line`, replacing the two `csv.DictReader` reads (`:1679-1680`, `:1928-1929`):
  ```python
  def read_input_rows(input_path: Path) -> list[dict]:
      if input_path.suffix.lower() == ".csv":
          with open(input_path, "r", encoding="utf-8") as f:
              return list(csv.DictReader(f))            # unchanged; preserves categ etc.
      import teitok_read                                 # stdlib reader; NOT flexiconv
      return [{"text": r["text"], "page_num": str(r["page_num"]),
               "line_num": str(r["line_num"]), "categ": ""}
              for r in teitok_read.read_teitok_rows(str(input_path))]
  ```
  Synthesized rows carry `categ=""` → treated as normal text by `_should_process_line`
  (only `min_char_count` applies); missing `quality_score` → `float(... or 0.0)`. No
  signature changes to `process_document*`; `file_id` derived via `doc_id_from_path`.
- Import wiring: guarded `sys.path.insert(0, str(Path(__file__).parent/"api_util"))` at the
  top of `llm_utils.py`/`llm_run.py` (mirrors `conftest.py`), then `import teitok_read`.
  `keywords.py` is run from repo root with `api_util` already on path via conftest; add the
  same guarded insert there.

### 5. Config (`config_api.txt`)

```bash
# Source directory for non-tabular documents converted via Flexiconv (api_flexiconv.sh).
INPUT_DOCS_DIR="$OUTPUT_DIR/DOCS"
# Extensions the Flexiconv step ingests (space/comma separated, no dot). Empty = disabled.
FLEXICONV_FORMATS="pdf docx odt rtf html htm md txt epub tei conllu vert folia srt"
```
`keywords.py`/`llm_run.py` need no new keys — point their existing `INPUT_DIR` (kw `-i`)
at `$OUTPUT_DIR/TEITOK` to process converted docs (documented). Defaults leave the tabular
pipeline and both enrichers behaving exactly as today.

## Edge cases & risks

- **TEITOK lacking lemma/POS** (plain docs) → legacy keywords sparse; yake/keybert fine. Documented.
- **Output naming** `.teitok.xml` double-suffix → `doc_id_from_path` strips it (kw id + llm out file).
- **Flexiconv missing** → only the conversion step fails (clear install hint, file skipped);
  the readers and tabular pipeline are unaffected.
- **Layout-free formats** → single page; `read_teitok_rows` still yields ordered lines.
- **Empty conversion** → skipped (conversion step) / empty enriched JSON (LLM), same as today.
- **Encoding** UTF-8 throughout; subprocess output decoded with `errors="replace"`.
- **Default behavior unchanged** — globs only add the new extension; flexiconv never imported
  unless `api_flexiconv.sh` runs.

## Verification

1. `pytest` — full suite green; new tests pass **without** Flexiconv installed (readers are
   stdlib; conversion tests mocked).
2. **Tabular regression:** run `api_1..4` on a CSV/XLSX `INPUT_TABLES_DIR` → identical outputs.
3. **Conversion:** put `sample.md`/`sample.txt` (and `.docx`/`.conllu` if Flexiconv installed)
   in `INPUT_DOCS_DIR`, run `api_flexiconv.sh` → `<doc>.teitok.xml` in `TEITOK_OUTPUT_DIR` +
   paradata; sanity-check the CLI with `flexiconv info formats` / `flexiconv -t teitok f out.xml`.
4. **Keywords on non-tabular:** `python3 keywords.py -i "$OUTPUT_DIR/TEITOK" -m yake` →
   keyword CSVs for the converted docs.
5. **LLM on non-tabular:** set `INPUT_DIR=$OUTPUT_DIR/TEITOK` in `llm_config.txt`, run
   `python3 llm_run.py` → `<doc>_enriched.json`.
6. **Missing-dep UX:** without Flexiconv, a `.docx` in `INPUT_DOCS_DIR` → clear install hint,
   file skipped, run continues.

### Current state review: 

**Issue #8: Add API Service**
The implementation of the FastAPI service wrapper brings the repository to a highly functional, deployable state. The codebase now cleanly abstracts the core shell scripts (`manifest`, `udp`, `nt`, `stats`) into accessible endpoints within `service/api.py`. It provides both synchronous processing (`/enrich`) and background task queues (`/jobs`) with a built-in semaphore to safely limit concurrent execution. Because the underlying categorization algorithm operates on strict quality-score thresholds rather than a cumulative penalty system, the API is highly efficient—it rapidly drops noisy or purely administrative lines early in the request lifecycle. This strict filtering safeguards the service from queue congestion and VRAM bottlenecks when executing the heavier LLM semantic enrichment stages.

**Issue #9: TEITOK Output Image Files Dependence Handling**
The source code addresses the facsimile alignment problem comprehensively. The standalone `fix_teitok_bboxes.py` script provides a direct mechanism to recalculate bounding boxes across entire directories using specific `dx`/`dy` shifts and `sx`/`sy` scale multipliers. Crucially, this capability is also smartly integrated into the live API via the `/rescale` endpoint. By automatically detecting the source dimensions and applying pure XML coordinate transformations, the codebase ensures that the TEITOK NLP annotations maintain perfect visual alignment over the page images, regardless of downstream resizing or cropping in the web viewer.

**Issue #10: Flexiconv-Supported Input Options**
The pipeline has successfully expanded its ingestion funnel to accommodate arbitrary text-containing formats. The `api_flexiconv.sh` script actively scans input directories and uses a regex pattern mapped to allowed extensions (via the `$FLEXICONV_FORMATS` variable) to route supported files through the `api_util/flexiconv_convert.py` wrapper. This establishes a clean, robust pre-processing hook that standardizes diverse raw inputs into the required TEITOK XML standard before they ever enter the UDPipe or NameTag components, keeping the core pipeline logic neatly unified.
