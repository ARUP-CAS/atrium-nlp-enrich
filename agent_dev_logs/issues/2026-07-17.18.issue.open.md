### Comparison

| Criterion | **INCEpTION** ⭐ | doccano | Label Studio | BRAT |
|---|---|---|---|---|
| Maintained (2026) | Yes, active | Yes | Yes | **No — v1.3, 2012; Python 2** |
| Model-in-the-loop / active learning | **Yes** (external recommender: spaCy/HF/**our LLM**) | No (import only) | Yes (ML backend) | No |
| Pre-annotation import | Yes (CoNLL/CAS/recommender) | **Yes, clean JSONL** | Yes (JSON preds) | Yes (write `.ann`) |
| Nested / overlapping spans | **Yes** | Weak/buggy | Yes | Yes (native) |
| Multi-annotator + curation + IAA | **Yes** | Multi-user, thin | Multi-user | No built-in |
| Export → CoNLL/IOB2 | Yes (+ small converter) | JSONL + converter | CoNLL2003 + converter | `.ann` + converter |
| Token-aligned export (import CoNLL-U) | **Yes** — tokens fixed to UDPipe's | Char-offset (re-align) | Char-offset (re-align) | Char-offset (re-align) |
| Setup / stateful footprint | Heaviest — MariaDB + own auth | **Lightest** | Medium (PG) | Medium, Python-2 pain |

### Recommendation: **INCEpTION** (fallback: **doccano**)

It maps 1:1 onto the workflow already designed in #7 and makes the correction step genuinely *faster* than the previously-assumed BRAT:
1. **Speed** — external-recommender API plugs in our existing constrained-decoding LLM stack (`llm_run.py`/`llm_utils.py`) and/or a bootstrapped NameTag/spaCy model that **active-learns as annotators work** (accept suggestions with a keystroke).
2. **Gold set** — multi-annotator curation/adjudication + inter-annotator agreement.
3. **Future-proof** — native nested/overlapping spans preserve `bronze = B-MATERIAL|B-ARTEFACT` for the deferred seq2seq v2, no re-annotation.
4. **Token-aligned** — import the UDPipe CoNLL-U so exported spans align exactly to NameTag's tokens.
5. Maintained + Docker (BRAT is Python-2, unmaintained since 2012 → not a safe 2026 container).

**Trade-off:** INCEpTION is the heaviest option and ships MariaDB + its own login — the project's first stateful/auth service. For a **standalone campaign** deploy it's self-contained in one `docker-compose`; the persistence/auth deviation from the no-DB/no-auth convention should be flagged to @rharasim before any shared hosting. If minimum setup + flat-v1-only is preferred, **doccano**'s JSONL import fits the LLM pre-annotations directly.

### Deployment (chosen: standalone campaign)

Own `docker-compose` on a UFAL/ARÚP host, used only for the campaign. Schema config + converters live in `atrium-nlp-enrich`; nothing is added to the runtime pipeline — the only contract with the pipeline is the exported IOB2 files.

### Common setup (tool-agnostic)

1. Freeze the `archaeo` scheme (6 types + boundary guidelines from #7) as `annotation/archaeo_tagset.json` + `GUIDELINES.md` (doubles as annotator handout).
2. `data_samples` CSV → token-segmented CoNLL-U via existing `api_util/call_udpipe.py`.
3. LLM pre-annotations via existing `llm_run.py::build_schema()/build_system_prompt()` + `llm_utils.py`.
4. Two small converters: `preannot_to_<tool>` (in) and `export_to_iob2` (out → two tab cols, `-DOCSTART-→O`, blank-line sentence breaks, `|`-joined overlaps; validate with NameTag's `preprocessing/iob_to_iob2.py`). The pipeline is already pipe-aware via `call_nametag.py::_get_ne_suffix()`.
5. Add archaeo entries to `api_util/summarize_nt_udp.py` tag maps (TEITOK interop: `LOCATION→LOC`, rest→`MISC`).

### INCEpTION usage flow

deploy (`inception` + `mariadb`) → create project, NE layer set to *"Any (stacked and overlapping)"* with the 6-value tagset → import CoNLL-U → wire external recommender (LLM/NameTag) + active learning (or batch-import predictions to start) → annotators correct → curate to gold + read IAA → export CoNLL → convert to IOB2 → into #7 training.

### Verification (tiny sample first)

Stand up tool → one Czech doc through UDPipe → LLM pre-annot → import → hand-correct ~10 sentences covering all 6 types incl. one overlap → export → convert → validate IOB2 (round-trips through `iob_to_iob2.py`, parses via `_get_ne_suffix()`) → NameTag training dry-run + `TAGSETS` registration → time annotators with vs. without recommenders to confirm the "fast" claim.

#### By GPT DeepResearch and High summary

From the comparison, **INCEpTION looks like the better fit** if the goal is **multiple people annotating the same documents with a proper review/curation workflow**.

**Why INCEpTION fits better here**

* Built for **document-centric collaborative annotation**.
* Has **separate roles** like annotator / curator / manager.
* Supports **curation**: multiple annotations on the same doc can be merged and conflicts resolved in the UI.
* Stores annotations as files on disk, with metadata in a SQL DB, which makes backups more predictable for text-heavy corpora.

**Where Label Studio is stronger**

* Better if we need **general-purpose labeling** across many data types.
* Easier for **bulk ingestion** at scale: API import and external/project storage are the fastest paths.
* But in Community Edition it is much weaker for team workflow: fewer access-control features, and no true INCEpTION-style curation/merge flow.

**Importing lots of documents**

* **Label Studio:** fastest path is usually API + external storage sync.
* **INCEpTION:** can import via UI or remote API, but it is more document-workflow oriented than bulk-ingestion oriented.

**Bottom line:** for this issue, if the main need is **many users + shared document annotation + curation**, I would lean **INCEpTION**. If the main need is **fast ingestion of a huge task set with simpler labeling**, Label Studio is stronger.

### Tool Comparison: INCEpTION vs. Label Studio (& Alternatives) - by Gemini Pro 3.1E Deep Research summary 

Based on the requirements for multi-user access, data curation workflows, storage management, and bulk ingestion for the ATRIUM NLP pipeline, here is a summary of the tool evaluation:

#### 1. INCEpTION (Recommended for Curation)
*   **Multi-User & Curation:** Excellent. Built specifically for text-heavy, document-centric workflows. Features dedicated roles (annotator, curator, manager) and a robust built-in UI for resolving annotation conflicts and merging them.
*   **Storage:** Stores annotations as files on disk (e.g., UIMA CAS XMI, TSV) with metadata in a SQL database, making backups predictable for academic corpora.
*   **Ingestion:** Supports UI or Remote API. Better suited for managed document workflows rather than raw, massive-scale automated bulk ingestion.

#### 2. Label Studio (Community Edition)
*   **Multi-User & Curation:** Weaker for complex linguistic workflows. The Community Edition lacks granular access control and a true INCEpTION-style curation/merge flow.
*   **Storage & Ingestion:** Excellent. Highly optimized for API bulk ingestion and external storage syncing (S3, GCS, local directories).
*   **Focus:** General-purpose labeling (images, audio, text) rather than specialized linguistic curation.

#### Alternatives for the UFAL / ATRIUM Ecosystem
Given the focus on `atrium-nlp-enrich` (NER, linguistic enrichment) and automated GitHub Actions workflows, two alternatives are worth considering:

*   **Argilla:** Highly recommended for a programmatic, developer-first approach. It integrates seamlessly with Hugging Face, spaCy, and transformer workflows. It excels at programmatic feedback loops and active learning, which fits perfectly into automated NLP pipelines.
*   **Doccano:** A lighter, open-source, text-specific alternative. It is very easy to spin up via Docker (fitting well with existing CI/CD setups) and handles text classification and sequence labeling nicely, though it lacks the advanced multi-user curation of INCEpTION.

#### Conclusion
*   If the main goal for Issue #18 is **collaborative curation and resolving annotator conflicts** on complex historical texts, **INCEpTION** is the strongest choice. 
*   If we need a **developer-centric, API-first** tool that tightly integrates with existing Python/transformer NLP pipelines, we should evaluate **Argilla**. 
*   If the absolute priority is **fast ingestion of huge task sets**, **Label Studio** wins.
