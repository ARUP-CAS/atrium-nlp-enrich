# Issue #18 — Annotation tool for NameTag NER training data: selection + setup/usage plan

Repo: `ufal/atrium-nlp-enrich` · Issue [#18](https://github.com/ufal/atrium-nlp-enrich/issues/18) (child of [#7](https://github.com/ufal/atrium-nlp-enrich/issues/7)) · Branch: `claude/ner-annotator-tool-plan-odtwpq`

## Context

Issue #7 locks the design for a **domain-specific archaeological NER model** trained on **NameTag 3** with a flat `archaeo` tagset of six types — **ARTEFACT, PERIOD, LOCATION, CONTEXT, MATERIAL, SPECIES**. The next unstarted step is **building training data**, whose intended flow is **LLM pre-annotate → human correction by archaeologists → export gold IOB2**. Issue #18 is the open sub-task: *"Pick one or create one tool for fast annotation of texts with new NE types"* — it suggests Vim macros or "open-source alternatives (BRAT)."

The planning docs (`agent_dev_logs/plans/7.plan.md`, the #7 issue doc) had **defaulted to BRAT for the correction step but never compared alternatives**. This plan does that comparison across the four candidates the user asked to evaluate (INCEpTION, doccano, Label Studio, BRAT), recommends one, and gives a concrete standalone (docker-compose) setup + usage plan that produces NameTag-3-ready IOB2 and reuses the existing pipeline pieces. Outcome: annotators can start producing a corrected gold set (5–10 files first, then ~10k entities/type) with the least friction, and the output drops straight into the #7 training loop.

### Hard requirements the tool must satisfy (from #7 + repo conventions)
- **Fast** annotation — the real speed lever is **model/LLM pre-annotation the annotator only corrects**, not labelling from scratch.
- Ingest **LLM pre-annotations** (their `llm_utils.py` stack already emits constrained JSON).
- Export to **NameTag 3 IOB2**: UTF-8, **two tab-separated columns** `token⇥label`, blank line between sentences, `-DOCSTART-→O`, **`|`-joined labels** for overlaps (e.g. `bronze → B-MATERIAL|B-ARTEFACT`). This is exactly what `api_util/call_nametag.py::_get_ne_suffix()` already parses, so the pipeline is pipe-aware today.
- **Czech** first (then Dutch/English), Unicode-safe, plus **Latin** taxonomic terms.
- **Multiple archaeologist annotators** (domain experts, likely non-technical) → simple UI; ideally curation + inter-annotator agreement to build a real "gold" set.
- Self-hosted, **open-source**, Docker.
- Deviation cost matters: the project runs **no DB and no auth anywhere** by deliberate design (flat-JSON "paradata", CORS-limited services); any tool with its own DB/auth is the first stateful service and must be flagged to the orchestration owner (Ronald Harasim / `rharasim`, ARÚB).

Dismissed quickly: **Vim macros** (single power-user only; no validation, IAA, or safe token-aligned export — fine only for a first tiny bootstrap gold set) and **Prodigy** (excellent model-in-the-loop but **commercial/closed** → fails the open-source requirement).

### Recommendation: **INCEpTION** (with **doccano** as the lightweight fallback)

INCEpTION maps 1:1 onto the workflow #7 already designed, and upgrades the planned "BRAT correction" step into something genuinely *faster* and higher-quality:
1. **Speed:** its **external-recommender API** lets us plug in (a) the existing constrained-decoding LLM stack (`llm_run.py::build_schema/build_system_prompt`, `llm_utils.py`) and/or (b) a bootstrapped NameTag/spaCy model that **active-learns as annotators work** — they accept suggestions with a keystroke instead of drawing every span. Neither BRAT nor doccano offers this.
2. **Gold set:** multi-annotator **curation/adjudication + inter-annotator agreement** — exactly the "golden dataset" goal in #7.
3. **Future-proof:** native **nested/overlapping** spans preserve `bronze = ART|MAT` for the deferred seq2seq v2 without re-annotation.
4. **Token-aligned export:** import the **UDPipe CoNLL-U** (tokens already produced by `api_util/call_udpipe.py`) so exported spans align to NameTag's tokens with no re-tokenisation drift.
5. Actively maintained + Docker (BRAT is Python-2, dead since 2012 → not a safe 2026 container).

Trade-off to accept and flag: INCEpTION is the heaviest option and brings **MariaDB + its own login** — the project's first stateful/auth service. For a **standalone campaign** deployment (chosen scope) this is self-contained in one docker-compose and operationally fine; raise the persistence/auth deviation with `rharasim` before any shared hosting. If the team prefers minimum setup and accepts flat-v1-only with no active learning, **doccano** is the clean fallback (its JSONL import fits the LLM pre-annotations directly).

## Deployment scope: standalone campaign (chosen)

Run the tool via its **own docker-compose** on a UFAL/ARÚP server or workstation, used only for the annotation campaign. The **schema config + converters live in `atrium-nlp-enrich`** (not a new productionised repo). Nothing is added to the runtime pipeline; the tool's only contract with the pipeline is the exported IOB2 files.

## Common setup — tool-agnostic (do this regardless of tool)

1. **Freeze the `archaeo` label scheme** as a shared config file in the repo (e.g. `annotation/archaeo_tagset.json`): the 6 types + the boundary guidelines already written in `agent_dev_logs/issues/2026-05-11.7.issue.open.md` (absorb descriptive adjectives, strip `circa/around` from PERIOD, strip `Municipality` from LOCATION, CONTEXT = man-made features only, human bones→ARTEFACT, split Latin vs colloquial species, etc.). This doubles as the annotator guideline handout.
2. **Prepare input** from Czech text lines (`data_samples/DOC_LINE_CATEG/*.csv`, `text` column) → sentence/token-segmented **CoNLL-U** via the existing `api_util/call_udpipe.py`. Tokenisation is fixed here so IOB2 export is token-exact.
3. **Generate LLM pre-annotations** with the existing stack: reuse `llm_run.py::build_schema()/build_system_prompt()` and `llm_utils.py::read_input_rows()/get_context_window()` to emit per-token or per-span archaeo labels as constrained JSON. Target ~10 sentences/type for the demo, scale toward ~10k entities/type.
4. **Two small converters** (new, under `atrium-nlp-enrich/annotation/` or `preprocessing/`), the only real code to write:
   - `preannot_to_<tool>`: LLM-JSON (+ CoNLL-U tokens) → the tool's import format (INCEpTION: pre-annotated CoNLL-U/UIMA CAS; doccano/LS: JSONL with spans; BRAT: `.ann`).
   - `<tool>_export_to_iob2`: tool export → NameTag IOB2 (two tab cols, `-DOCSTART-→O`, blank-line sentence breaks, `|`-joined overlaps). Validate/normalise with NameTag 3's `preprocessing/iob_to_iob2.py`. Keep the `_get_ne_suffix()` pipe convention in `api_util/call_nametag.py` as the reference.
5. Extend the tag dictionaries for downstream display: add archaeo entries to `api_util/summarize_nt_udp.py` (`CNEC_TYPE_MAP`/`get_ne_explanation()`), and the TEITOK `@type` interop (`LOCATION→LOC`, rest→`MISC`).

## Recommended tool setup & usage — INCEpTION

1. **Deploy** (standalone): `docker-compose.yml` with `inceptionproject/inception` + `mariadb` (set `MARIADB_AUTO_UPGRADE=1`), named volumes for `/export` and the DB, admin user via env. One `docker compose up -d`.
2. **Project + layer:** create an annotation project; on the built-in **Named entity** span layer set behaviour to **"Any (stacked and overlapping)"** and attach a tagset made of the 6 archaeo values; upload the guideline doc from step 1.
3. **Load data:** import the UDPipe **CoNLL-U** documents (tokens fixed to NameTag's).
4. **Wire recommenders (the speed win):** stand up an **external recommender** web service (the `inception-external-recommender` Flask template) wrapping either the LLM stack or a bootstrapped NameTag/spaCy model; enable **active learning** so suggestions improve as annotation proceeds. Start simpler with a **batch pre-import** of LLM predictions if the recommender service isn't ready day one.
5. **Annotate/correct:** archaeologists accept/adjust inline suggestions; use multiple annotators per doc.
6. **Curate → gold:** adjudicate on the **curation** page; read **inter-annotator agreement**.
7. **Export → convert:** export CoNLL → run `inception_export_to_iob2` → NameTag IOB2. Feed straight into #7's training.

### Setup notes for the other three (so the plan covers all four)
- **doccano:** `docker compose` (doccano image + DB); create a **Sequence Labeling** project + 6 labels; **import JSONL** carrying LLM pre-annotation spans; annotate; export JSONL → `doccano_export_to_iob2`. Fastest to stand up; no active learning; keep spans non-overlapping for clean flat-v1 (log overlaps separately if needed).
- **Label Studio:** `docker compose`; NER labelling config with 6 labels; import tasks with `predictions` (LLM pre-annotations); optional **ML backend** for active learning; export **CONLL2003** → normalise to the 2-col pipe format.
- **BRAT (only if explicitly chosen):** containerise on legacy Python; `annotation.conf` with the 6 entity types; write LLM pre-annotations as `.ann` (char offsets over the raw text) for correction; convert `.ann` → IOB2. Accept the maintenance/security risk.

## Verification (end-to-end, on a tiny sample before scaling)
1. `docker compose up -d` the chosen tool; confirm the web UI loads and the archaeo project/labels exist.
2. Run one `data_samples` Czech doc through `call_udpipe.py` → CoNLL-U → LLM pre-annotation → import; confirm suggestions appear in the UI.
3. Hand-correct ~10 sentences covering all 6 types (incl. one overlap like `bronze`); export; run `export_to_iob2.py`.
4. **Validate the IOB2**: exactly two tab-separated columns, blank lines between sentences, `-DOCSTART-→O`, pipe-joined overlaps; round-trip through NameTag's `preprocessing/iob_to_iob2.py` with no errors; confirm `api_util/call_nametag.py::_get_ne_suffix()` parses the multi-labels.
5. Smoke-test consumption: a NameTag 3 training dry-run on the tiny set (or at minimum tagset-registration in `nametag3_dataset.py`'s `TAGSETS`) to prove the file is training-ready — closing the loop into #7 Phase 1.
6. Record annotator wall-clock on the 10-sentence sample with vs. without recommender suggestions to confirm the "fast" claim before the full campaign.
