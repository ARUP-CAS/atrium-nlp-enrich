# Strategy — Issue #8: API service for NLP-enriched TEITOK XML

> Issue [#8](https://github.com/ufal/atrium-nlp-enrich/issues/8) · Labels: `enhancement`, `development` · **Status: 🔍 Tocheck**

## Context
A FastAPI service wraps the whole enrichment pipeline (`manifest → udp → nt → stats`) behind
`/enrich`, `/enrich_text`, `/jobs`, `/rescale`, `/health`, `/info`, taking ordered text lines and
returning enriched `teitok.xml` (+ keywords + LLM JSON). It shipped (v0.12.0 CLI-tested) and the
merged `run_pipeline.py` driver underpins it; the service has since been refactored into a package
(`api.py`/`enrichment.py`/`jobs.py`/`rescale.py`). A **13-item self-audit** drove the work — and
on a fresh walk of `test` HEAD (2026-06-26) **all 13 are resolved** (11 fixed, 2 consciously
documented). Status stays `Tocheck` because three strategy-conformance items remain and the
service has not had a real-deployment pass.

## Strategic actions

### A — Version single-source-of-truth (F1)
1. Add `_read_tool_version()` to `service/api.py` that reuses
   `atrium_paradata._load_para_config(_SERVICE_DIR.parent)` (`atrium_paradata.py:40-68`), strips a
   leading `v`, falls back to `"unknown"`. Use it for `FastAPI(version=...)` and add a `"version"`
   key to `/info`, so `/info`, `CITATION.cff` and the release tag can't drift (CI
   `security.reusable.yml` already cross-checks them). Do **not** write a new INI reader.

### B — Strategy-conformance gaps
2. Add a `"device"` key to `/info` via a guarded detector
   (`torch.cuda.is_available()` → `"cuda"`/`"cpu"`; missing torch → `"cpu"`/`"unknown"`, never
   raises), mirroring the device tag `keywords.py` prints when loading KeyBERT.
3. Add an `nlp-api:` block to `docker-compose.gpu.yaml` with the same
   `NVIDIA_VISIBLE_DEVICES: all` + `deploy.resources.reservations.devices` (nvidia/all/gpu) shape
   as `nlp`/`nlp-llm`, and update the header comment for the `--profile api` invocation.

### C — Real-deployment test (close-out gate)
4. Run the service in a real container (`setup_api_service.sh` or
   `docker compose --profile api up`); exercise `/enrich` (json + zip), `/enrich_text`, `/jobs`
   (queue→done→result→delete), `/rescale`, `/health`, `/health?deep=true`, `/info`. Confirm
   `/info` reports the real version + device and that the GPU profile places KeyBERT on CUDA. If a
   live container/GPU isn't available here, record this as the remaining `Tocheck` gate.
