# Strategy — Issue #8: API service for NLP-enriched TEITOK XML

> Issue [#8](https://github.com/ufal/atrium-nlp-enrich/issues/8) · Labels: `enhancement`, `development` · **Status: 🔍 Tocheck**

## Context
A FastAPI service wraps the whole enrichment pipeline (`manifest → udp → nt → stats`) behind
`/enrich`, `/enrich_text`, `/jobs`, `/rescale`, `/health`, `/info`, taking ordered text lines
and returning enriched `teitok.xml` (+ keywords + LLM JSON). It shipped (v0.12.0 drafted/CLI-
tested; `test` HEAD at v0.15.0) and the merged `run_pipeline.py` driver underpins it. A
**careful 13-item self-audit** drives the remaining work: the two highest-impact bugs
(`num_keywords` dead-ends, `zip` workspace leak) are **fixed on HEAD**; several robustness items
need verification, and there's a version-drift docs gap. Status is `Tocheck`: deployable, but
needs a real-deployment pass + the audit closed.

## Strategic actions

### Phase A — Close the verified-fix gap (turn ⚠️ into ✅ or 📝)
Walk the audit against `test` HEAD and, for each ⚠️ item, either confirm the fix landed or
implement it:
1. **#3 warmup** — stop `sys.exit(1)` inside `_get_keybert_model` (raise instead), or catch
   `BaseException` in `warmup`, so a model-load failure **degrades to yake** instead of failing
   lifespan startup.
2. **#4 runtime keybert failure** — separate "empty run" from "keybert crashed" (distinct exit
   codes) so a keybert problem *after* TEITOK already succeeded degrades rather than returning
   502 on a successful enrichment.
3. **#6 `/jobs` validation** — call `_validate_params` in `submit_job` (clean 422 at submission,
   not a failed background job).
4. **#7 `DELETE /jobs/{id}`** — remove the dead `rmtree(_API_JOBS_ROOT/job_id)` (wrong uuid) or
   make it target the real workspace.
5. **#9, #12, #13** — fix the fresh-workspace `skipped>=total` heuristic; either wire `lang`
   through or drop it (it will silently no-op the moment a second language is added); anchor
   `StaticFiles` to `_SERVICE_DIR`.

### Phase B — Strategy-conformance gaps
6. Add the **`device`** key to `/info` (hardware execution context, per the spec).
7. Add the **`nlp-api`** service to `docker-compose.gpu.yaml` with NVIDIA reservations so
   KeyBERT actually uses CUDA under `--profile api`, instead of silently falling to CPU.

### Phase C — Version single-source-of-truth (F1)
8. Replace the hard-coded `FastAPI(version="0.11.0")` with `_read_tool_version()` reading
   `para_config.txt [tool] version` (the CONTRIBUTING recipe) so `/info`, `CITATION.cff` and the
   release tag can never drift again. CI (`security.reusable.yml`) already validates the three
   agree.

### Phase D — Long-lived-service hardening (#10)
9. Add **TTL / eviction** to `_jobs` before any deployment that outlives a demo. Document the
   warmup honesty caveat (#8: the per-request subprocess reloads the sentence-transformer; the
   in-process warmup only pre-populates the HF disk cache).

### Phase E — Real-deployment test
10. The v0.12.0 release was **CLI-tested only**. Run the service in a real container
    (sync + `/jobs` + `/rescale`), confirm the `/health` partial (config-only) is acceptable or
    add the spec'd LINDAT reachability probe.

## Verification / done-criteria
- Every audit item is ✅ fixed or 📝 consciously documented as a limitation.
- `/info` reports `device`; GPU profile actually places KeyBERT on CUDA.
- API version is read from config (no drift); `pytest` fast lane green.
- A real deployment run passes sync + background + rescale paths.
