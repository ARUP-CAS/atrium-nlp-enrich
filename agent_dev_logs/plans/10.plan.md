# Strategy — Issue #10: Flexiconv-supported input formats

> Issue [#10](https://github.com/ufal/atrium-nlp-enrich/issues/10) · Labels: `enhancement`, `development`, `a big one` · **Status: 🔍 Tocheck — implemented + test-covered; real-practice conversion run pending (issue open)**

## Context
The pipeline can now ingest **any Flexiconv-supported non-tabular format** (pdf, docx, odt, rtf,
html, md, txt, epub, tei, conllu, …) by converting it **directly to TEITOK XML** — bypassing
UDPipe/NameTag — while keyword extraction and LLM enrichment were extended to **discover and
read** those `.teitok.xml` files via a shared, **stdlib-only** reader. CSV/XLSX keep stages 1–4
unchanged; Flexiconv is an **optional, lazily-imported** dependency. 

The implementation landed initially in `efbf8b8`; `5f34f982` ("add tests and fixtures for issue #10")
resolved the test-coverage gap. The dependency is strictly pinned and spatial coordinate alignments
for PAGE XML/hOCR are established in the test suite. **Caveat (K4TEL, 2026-06-28): the flexiconv
conversion itself has not been tested in practice yet — the issue stays open until real
conversion experiments are conducted.**

## B — Validation specifics
### A — Format + data validation
1. **Text conservation:** `<s text="...">` matches the raw text, and `<tok>` reconstruction
   matches exactly (honouring `join=right` / `spaceAfter=No`).
2. **NER wrappers:** `NER=B-P|I-P` in CoNLL-U correctly wraps tokens in `<name type="PER">`.
3. **Coordinate logic:** `api_4_stats.sh` scaling aligns PAGE XML and hOCR bboxes without regressions.

### B — Integration
4. **Keywords:** run `keywords.py -i $OUTPUT_DIR/TEITOK -m yake`. (Note: legacy KER backend
   will produce poor/empty results without base lemmas on layout-free docs
   (no POS), **yake/keybert** work regardless.)
5. LLM: set `INPUT_DIR=$OUTPUT_DIR/TEITOK`, run `llm_run.py` → `<doc>_enriched.json`;
   `doc_id_from_path` successfully strips the double `.teitok.xml` suffix.
6. Synthesized `categ=""` rows are treated as normal text by `_should_process_line`
   (only `min_char_count` gates them) and missing `quality_score` defaults to 0.0 safely.

### C — Regression + UX guards
7. **Tabular regression:** rerun `api_1..4` on a CSV/XLSX `INPUT_TABLES_DIR` → byte-identical
   outputs.
8. **Missing-dep UX:** a `.docx` in `INPUT_DOCS_DIR` **without** Flexiconv installed → clear
   install hint to stderr + paradata `skip`, file skipped, run continues, readers/tabular unaffected.
9. `pytest` passes **without** Flexiconv (readers are stdlib; conversion tests mock the
   lib + `subprocess`/`shutil.which`).

# Plan — Visually-rich Markdown converter for DOCX / PDF inputs (issue #10)

Repo: `ufal/atrium-llm-enrich` · Branch: `claude/docx-pdf-markdown-conversion-8ocily`

## Context

Issue [#10](https://github.com/ufal/atrium-llm-enrich/issues/10) asks how to turn input **PDFs**
(curve-only / scanned / digital-born) and **DOCX** into LLM-friendly inputs. A **research pass**
already landed (`agent_dev_logs/plans/10.plan.md` + `digests/10.digest.md`): it surveyed tools,
picked permissive-first routing, and deliberately landed **no converter code**. Two new issue
comments (2026-07-21) move it to *implementation*: convert PDF/DOCX → **visually-rich Markdown** in
which page borders and layout cues are recorded as **HTML comments** inside the `.md`, so the LLM
sees layout signal it would otherwise lose. Comment #2 gives an exhaustive **taxonomy** of those
cues and their exact encoding (`<!-- PAGE_BREAK: pg_12 -->`, `<!-- BBOX: [...] -->`,
`<!-- FONT: size=14pt, weight=700 -->`, `<!-- HEADER_START -->`, `~~strike~~`, `<u>…</u>`,
`<div align="center">…</div>`, footnotes, tables, `<!-- WATERMARK: … -->`, …).

**Why this design.** The pipeline already has a document-level entry point: `run_document_level()`
in `llm_client_shared.py:557` reads a `.md`/`.txt` file and makes one LLM call per document. Today
that `.md` is produced by `api_util/xml_to_md.py` (page-sectioned `## Page N` Markdown). So the job
is a **new front-end that lands a `.md` in `INPUT_DIR`** — no dispatch change needed
(`llm_run.py:411-414` reads only `.csv`/`.teitok.xml`; the remote/ollama clients pick up `.md`).
HTML comments are inert text, so they pass straight through `run_document_level()` to the model.

**Decisions (confirmed with user):**
1. **Scope:** DOCX **+ digital-born PDF** now — both permissive & CPU-light, no model downloads.
   Scanned/curve-only PDFs get a clear `<!-- NEEDS_OCR … -->` marker; the OCR path (Tesseract/PERO,
   models/GPU) stays a benchmark-gated follow-up (aligns with hub `atrium-project#22`).
2. **Integration:** **standalone pre-convert CLI**, mirroring `xml_to_md.py` /
   `flexiconv_convert.py` — run it, the `.md` lands in `INPUT_DIR`, run the pipeline unchanged.
3. **Cue coverage:** **pragmatic high-value core** of the taxonomy, single-sourced and extensible.

**Tooling (permissive-first, matches UFAL license pressure in `para_config.txt`).** flexiconv is
license-blocked; Docling's PDF path needs HuggingFace downloads (blocked by the env network policy).
So: **python-docx** (MIT) for DOCX (richest native styling metadata) and **pdfplumber** (MIT) for
digital-born PDF (page dims, word/char bboxes, font name/size, tables). Both lazily imported so the
base repo never requires them. *(None are installed in this env — see Verification.)*

## Approach

Four small modules in `api_util/` (matching the repo's one-focused-file-per-tool style), plus tests,
an optional requirements file, and doc/devlog updates.

### 1. `api_util/layout_md.py` — the cue vocabulary (dependency-free)
The "list of all possible visual layout pieces" made executable and single-sourced. Pure functions
returning the **exact** HTML-comment / Markdown strings from comment #2, so both converters emit one
canonical schema:
- Block/page: `page_break(page_id)`, `doc_meta(size, orientation)`, `bbox([x0,y0,x1,y1])`,
  `layout_margin(...)`, `layout_column(i, n)`, `needs_ocr(page_id, reason)`.
- Inline/style: `font(size=, weight=, family=)`, `style(color=, highlight=, line_spacing=)`,
  `bold`, `italic`, `strike` (`~~…~~`), `underline` (`<u>…</u>`), `align_div(content, align)`.
- Regions: `header_start/header_end`, `footer_start/footer_end`, `watermark(text)`, `footnote_ref`,
  `footnote_def`, `image(alt, src, bbox=…)`.
- A `CUE_SCHEMA` registry (name → description) documenting the full taxonomy for reference/tests.

### 2. `api_util/docx_to_md.py` — DOCX → visually-rich MD (lazy `import docx`)
Walk body blocks (paragraphs + tables in order). Map: paragraph **style** → headings; **runs** →
bold/italic/underline/strike + `font(size/family)` + `style(color/highlight)` cues; paragraph
**alignment** → `align_div`; **tables** → GFM; section **headers/footers** → `HEADER_*`/`FOOTER_*`
blocks; section **margins** → `layout_margin`; **page breaks** (`WD_BREAK.PAGE` / `w:br w:type=page`)
→ `page_break` + `## Page N`; **images** → `image()` placeholder; **footnotes** → `[^n]` refs+defs.

### 3. `api_util/pdf_to_md.py` — digital-born PDF → visually-rich MD (lazy `import pdfplumber`)
Per page: emit `doc_meta` (page.width/height) once, `## Page N` + `page_break`. If a page has
≈no extractable characters → emit `needs_ocr` and skip (deferred class). Otherwise cluster
words/lines into blocks → per-block `bbox` + `font` (from char `fontname`/`size`) + text; tables via
`page.extract_tables()` → GFM. Include the plan's **decode-sanity check** (ratio of
replacement/control/out-of-script codepoints) — a page that extracts *garbled* Czech (the no-
`/ToUnicode` case) is also flagged `needs_ocr` rather than trusted.

### 4. `api_util/doc_to_visual_md.py` — dispatcher + unified CLI
`convert_to_visual_md(path) -> str` routes by extension (`.docx`→docx, `.pdf`→pdf; clear error for
unsupported / OCR-only). `__main__` mirrors `xml_to_md.py`'s CLI: `input_file [--output out.md]`.
Reuse `doc_id_from_path()` (`api_util/teitok_read.py:5`) for the `# <title>` and match
`xml_to_md.py`'s `## Page N` sectioning so the document-level system prompt's page-locator
instructions resolve.

### 5. Deps, tests, docs
- **`requirements_docmd.txt`** (new): `python-docx`, `pdfplumber` — optional, mirrors
  `requirements_flexiconv.txt`; base install stays light.
- **Tests** (pytest, hermetic, `tmp_path`, `skipif` on missing lib — mirror
  `tests/test_xml_to_md.py` / `test_flexiconv_convert.py`):
  - `tests/test_layout_md.py` — exact-string unit tests for every emitter (no heavy deps → always runs).
  - `tests/test_docx_to_md.py` — build a tiny `.docx` with python-docx, assert heading/bold/table/
    page-break/header cues.
  - `tests/test_pdf_to_md.py` — small committed fixture PDFs under `tests/fixtures/` (one digital-born,
    one text-less) → assert `DOC_META`/`PAGE_BREAK`/`BBOX`/`FONT` on the first and `NEEDS_OCR` on the
    second; plus a pure-string decode-sanity unit test.
  - No `slow` marks needed (no network/models); library gating via import `skipif`.
- **Docs:** README — add a "Visually-rich document input" subsection beside *Document-Level Input*
  (`README.md:219`), the input-modes note, the optional install line, and a tool footnote. Update
  `agent_dev_logs/plans/10.plan.md` + `digests/10.digest.md` status (research → first implementation
  landed; OCR deferred). Leave the flagged stale `DEVLOG.md` untouched.

### Reuse (don't reinvent)
`doc_id_from_path()` (`teitok_read.py:5`); `xml_to_md.py`'s `## Page N` sectioning, `convert()` shape
& CLI; the decode-sanity heuristic from plan §1; the lazy-import + `*_available()` pattern from
`flexiconv_convert.py`; landing `.md` in `INPUT_DIR` for `run_document_level()` (no dispatch change).
