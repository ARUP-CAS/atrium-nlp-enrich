# Strategy — Issue #10: Flexiconv-supported input formats

> Issue [#10](https://github.com/ufal/atrium-nlp-enrich/issues/10) · Labels: `enhancement`, `development`, `a big one` · **Status: 🔍 Tocheck**

## Context
The pipeline can now ingest **any Flexiconv-supported non-tabular format** (pdf, docx, odt, rtf,
html, md, txt, epub, tei, conllu, …) by converting it **directly to TEITOK XML** — bypassing
UDPipe/NameTag — while keyword extraction and LLM enrichment were extended to **discover and
read** those `.teitok.xml` files via a shared, **stdlib-only** reader. CSV/XLSX keep stages 1–4
unchanged; Flexiconv is an **optional, lazily-imported** dependency. The full implementation
landed (`efbf8b8`) and every file is present on `test` HEAD. The one open thing — and the reason
the status is `Tocheck` — is that it was **"not tested in practice with real out-of-scope file
formats."** This plan is the verification + hardening pass to close it.

## Strategic actions

### A — Run the live conversion test (the close-out gate)
1. Install Flexiconv and run `api_flexiconv.sh` over a **real** mixed `INPUT_DOCS_DIR`
   (`sample.md`, `sample.txt`, a real `.docx`, a `.conllu`) → expect `<doc>.teitok.xml` in
   `TEITOK_OUTPUT_DIR` + paradata. Sanity-check the CLI: `flexiconv info formats`,
   `flexiconv -t teitok in out.xml`.
2. **Verify the lib→CLI fallback** against the real library: confirm the Python entry point
   (`import flexiconv` → convert to `teitok`) works, and that removing it cleanly falls through
   to the `shutil.which("flexiconv")` CLI path.
3. **Pin** `flexiconv` in `requirements_flexiconv.txt` to the verified version.

### B — Downstream-read verification on real converted docs
4. Keywords: `python3 keywords.py -i "$OUTPUT_DIR/TEITOK" -m yake` → keyword CSVs. Confirm the
   documented caveat empirically: **legacy** method yields sparse lemmas on layout-free docs
   (no POS), **yake/keybert** work regardless.
5. LLM: set `INPUT_DIR=$OUTPUT_DIR/TEITOK`, run `llm_run.py` → `<doc>_enriched.json`; confirm
   `doc_id_from_path` strips the double `.teitok.xml` suffix so outputs aren't `X.teitok_enriched.json`.
6. Confirm synthesized `categ=""` rows are treated as normal text by `_should_process_line`
   (only `min_char_count` gates them) and that missing `quality_score` defaults to 0.0 safely.

### C — Regression + UX guards
7. **Tabular regression:** rerun `api_1..4` on a CSV/XLSX `INPUT_TABLES_DIR` → byte-identical
   outputs (proves the new globs only *add* the TEITOK extension).
8. **Missing-dep UX:** a `.docx` in `INPUT_DOCS_DIR` **without** Flexiconv installed → clear
   install hint to stderr + paradata `skip`, file skipped, run continues, readers/tabular
   unaffected.
9. Confirm `pytest` passes **without** Flexiconv (readers are stdlib; conversion tests mock the
   lib + `subprocess`/`shutil.which`).

## Verification / done-criteria
- A real multi-format conversion run produces valid TEITOK + paradata; the lib→CLI fallback is
  proven; the `flexiconv` version is pinned.
- Keywords and LLM enrichment both read the converted `.teitok.xml` with clean ids/outputs.
- Tabular pipeline byte-identical; missing-dep path degrades gracefully; fast lane green.
